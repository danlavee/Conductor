# Establish shared working agreements

## Situation

A user is coordinating agents with separate conversations and needs them to follow the same rules and organize shared information consistently.

## Goal

Every agent should know how the team works and where different kinds of shared information belong.

## What happens

1. The user establishes the team's working rules and chooses predictable names for broad areas and the subjects within them.
2. An agent publishes that guidance in the team's agreed place for shared working agreements.
3. The current agreements become available to every agent, and the team is notified when they change.
4. Agents apply the rules relevant to their work and use the agreed names when sharing or reading information.
5. Each subject contains independently named items. Publishing the first item creates its shared location when needed.
6. An agent that joins later receives the current agreements with the team's existing shared material before it acts.
7. The user can revise the same shared guidance as the team's needs change.

Conductor does not currently provide a directory for browsing available areas and subjects, so their names must be established in the working agreements or a team handoff.

## Outcome

The user maintains one shared operating baseline that tells agents both how to collaborate and where information belongs.
