# Conductor state protocol

Exact, non-obvious mechanism facts only — what `SKILL.md`, `commands.md`, or `limitations.md` already say isn't repeated here.

- A new record takes the topic's highest index plus one; a separate per-topic `sequence` orders the topic's publications.
- A publication is the atomic result of one write to one topic: `sequence`, `topic`, `agent`, `timestamp`, and the changed `records`. It is visible, and wakes its readers, the moment it is appended to history. Every record command is one publication under an OS file lock on its topic; a `--jsonl` load is the only multi-record one, all or nothing.
- `recipients` are resolved at publication from who is subscribed at that instant (everyone, for `collaboration/rules`, `collaboration/agents` and `collaboration/broadcast`; only `<name>`, for `private/<name>`), less the publisher. They are not persisted: a stored audience would be falsified by the next subscription change.
- A delta read skips your own publications but reads past them. A delta always includes its first qualifying publication whole, even past the cap.
- The 2,000-character record limit counts Unicode code points and holds on every write path, the struck-through roster line included.
- One delivery is a delta of every readable topic with unread publications, up to a shared budget of 20 records (`{"deliveries": [...], "remaining": N, "default_read_limit": 20}`), taken in topic order. A publication is never split: each topic's delta takes the whole publications that fit what is left of the budget, and later topics share the rest, but a topic whose first unread publication alone exceeds what is left waits for the next delivery, with every topic after it.
- A wake shows a delivery as plain text: whole publications, at most 5 records within 10,000 characters (UTF-16 code units), framing included, and a closing line counting what it left unread. Only what it showed is acknowledged; the rest follows on the next wake. On hosts whose adapter has an in-turn hook, that hook also writes one.
- `watch` writes one wake, acknowledges what it showed, and exits. stdout carries that wake and nothing else; a failed wait exits non-zero with stdout empty. A blocked `watch` whose agent leaves returns `NOT_FOUND`.
- One ownership lock per identity: a second watcher, or a `watch` beside an adapter, gets `LOCKED` naming the PID that holds it, so any number of restore attempts converge on one stream.
- `protocol.json` gates the state root: a malformed or mismatched declaration returns `PROTOCOL_MISMATCH` before anything runs. A missing one is written by the next agent command, except `watch`, which attaches only to a declared root and refuses with `PROTOCOL_MISMATCH`. There is no migration; a new protocol starts a fresh state root. Persisted JSON shapes are pinned by a wire-compatibility test, so changing one forces a protocol bump.
